# Logging with Diagnostic Explorer

Diagnostic Explorer can route logs from log4net, Microsoft.Extensions.Logging (MEL), Serilog, or NLog into named Diagnostic Explorer event sinks. Each integration sends events through the same route model, so applications can keep the same namespace-to-sink rules while changing logging frameworks.

Choose one Diagnostic Explorer logging integration for each event path. Registering more than one for the same events intentionally produces duplicate Diagnostic Explorer events.

## Packages

| Logging framework            | Diagnostic Explorer package             |
| ---------------------------- | --------------------------------------- |
| log4net                      | `DiagnosticExplorer.Log4Net`            |
| Microsoft.Extensions.Logging | `DiagnosticExplorer.Extensions.Logging` |
| Serilog                      | `DiagnosticExplorer.Serilog`            |
| NLog                         | `DiagnosticExplorer.NLog`               |

The framework-specific package references the core `DiagnosticExplorer` package. Configure remote hosting or self-hosting independently; the logging integrations write to `EventSinkRepo.Default`, which is then exposed by the configured Diagnostic Explorer host.

## Shared Routing Configuration

Put routes under an application-owned `DiagnosticExplorer:Routing` section. The hosting URL shown below is optional and unrelated to logging routing.

```json
{
  "DiagnosticExplorer": {
    "Url": "http://localhost:2803/diagnostics",
    "Routing": {
      "MatchMode": "AllMatches",
      "Routes": [
        {
          "CategoryPattern": "MyCompany.MyApp.Orders",
          "MinLevel": "Information",
          "Destinations": [
            {
              "SinkName": "Order Events",
              "SinkCategory": "Orders"
            }
          ]
        },
        {
          "CategoryPattern": "*",
          "MinLevel": "Warning",
          "MaxLevel": "Warning",
          "Destinations": [
            {
              "SinkName": "Warnings",
              "SinkCategory": "System"
            }
          ]
        },
        {
          "CategoryPattern": "*",
          "MinLevel": "Error",
          "Destinations": [
            {
              "SinkName": "Errors",
              "SinkCategory": "System"
            }
          ]
        }
      ]
    }
  }
}
```

`CategoryPattern` is case-insensitive. A value such as `MyCompany.MyApp.Orders` matches that exact category and child categories such as `MyCompany.MyApp.Orders.Processing`; it does not match `MyCompany.MyApp.OrderSummary`. `*` matches every category.

Routes can set `MinLevel`, `MaxLevel`, `StopProcessing`, and one or more destinations. Duplicate `(SinkName, SinkCategory)` destinations are written once per event.

`MatchMode` controls overlapping routes:

| Value          | Behavior                                                                                |
| -------------- | --------------------------------------------------------------------------------------- |
| `AllMatches`   | Writes to every matching route. This is the default and supports warning/error fan-out. |
| `MostSpecific` | Writes only to the longest matching namespace prefix.                                   |
| `FirstMatch`   | Writes only to the first matching route in configuration order.                         |

Routing is bound at startup. Restart the process after changing routes.

## log4net

Reference `DiagnosticExplorer.Log4Net`. Configure one `RoutingDiagnosticAppender`; it reads the shared JSON route section and keeps namespace routing out of `log4net.config`.

```xml
<log4net>
  <root>
    <level value="ALL" />
    <appender-ref ref="DiagnosticExplorerRouter" />
  </root>

  <appender name="DiagnosticExplorerRouter"
            type="DiagnosticExplorer.Log4Net.RoutingDiagnosticAppender, DiagnosticExplorer.Log4Net">
    <ConfigurationFile>config.json</ConfigurationFile>
    <ConfigurationSection>DiagnosticExplorer:Routing</ConfigurationSection>
  </appender>
</log4net>
```

Initialize log4net normally:

```csharp
using log4net.Config;

XmlConfigurator.ConfigureAndWatch(new FileInfo("log4net.config"));
```

The router uses `LoggingEvent.LoggerName` as the category. Keep unrelated log4net appenders, such as SMTP or debug output, in the XML configuration. Its native `NOTICE` level maps to Diagnostic Explorer's `Information` level.

## Microsoft.Extensions.Logging

Reference `DiagnosticExplorer.Extensions.Logging`, then add the provider to the logging builder:

```csharp
using DiagnosticExplorer.Extensions.Logging;

builder.Logging.AddDiagnosticExplorer(
    builder.Configuration.GetSection("DiagnosticExplorer:Routing"));
```

MEL uses the `ILogger` category, including the category generated by `ILogger<T>`. Normal MEL filtering occurs before the Diagnostic Explorer provider sees an event, so configure `Logging:LogLevel` to include the events you want routed:

```json
{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "MyCompany.MyApp": "Trace"
    }
  }
}
```

The provider preserves the rendered message, exception, `EventId`, structured state, and external scopes in the Diagnostic Explorer event detail.

## Serilog

Reference `DiagnosticExplorer.Serilog` and Serilog. Bind the shared route options and attach one Diagnostic Explorer sink:

```csharp
using DiagnosticExplorer.Logging;
using DiagnosticExplorer.Serilog;
using Microsoft.Extensions.Configuration;
using Serilog;

EventSinkRouteOptions routes = ConfigurationBinder.Get<EventSinkRouteOptions>(
    configuration.GetSection("DiagnosticExplorer:Routing"));

Log.Logger = new LoggerConfiguration()
    .MinimumLevel.Information()
    .WriteTo.DiagnosticExplorer(routes)
    .CreateLogger();
```

Serilog routes by `SourceContext`. If the application logs through the Serilog MEL provider, it is assigned automatically. For direct Serilog usage, set it explicitly:

```csharp
Log.ForContext("SourceContext", "MyCompany.MyApp.Orders")
    .Information("Order {OrderId} accepted", orderId);
```

Set Serilog's minimum level and filters independently. They decide whether the sink receives an event; Diagnostic Explorer routes decide its destination sinks.

## NLog

Reference `DiagnosticExplorer.NLog` and NLog. Create one Diagnostic Explorer target, add it to the NLog configuration, and apply normal NLog rules:

```csharp
using DiagnosticExplorer.Logging;
using DiagnosticExplorer.NLog;
using Microsoft.Extensions.Configuration;
using NLog;
using NLog.Config;

EventSinkRouteOptions routes = ConfigurationBinder.Get<EventSinkRouteOptions>(
    configuration.GetSection("DiagnosticExplorer:Routing"));

LoggingConfiguration nlogConfiguration = new();
nlogConfiguration.AddDiagnosticExplorer("diagnosticExplorer", routes);
nlogConfiguration.AddRuleForAllLevels("diagnosticExplorer");
LogManager.Configuration = nlogConfiguration;
```

NLog routes by `LogEventInfo.LoggerName`, usually the name passed to `LogManager.GetLogger(...)`. NLog rules are still the preliminary level/category filter; the shared route options choose the Diagnostic Explorer event sinks.

## Verify the Setup

Emit an event in a known category and inspect the matching sink in the Diagnostic Explorer viewer:

```csharp
logger.LogInformation("Order {OrderId} accepted", orderId);
```

With the shared example configuration, an `Information` event from `MyCompany.MyApp.Orders` appears in `Order Events / Orders`. A warning from that category appears in both `Order Events / Orders` and `Warnings / System` when `MatchMode` is `AllMatches`.
